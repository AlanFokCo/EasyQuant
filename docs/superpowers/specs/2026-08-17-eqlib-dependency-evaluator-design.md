# eqlib 依赖对抗性 Evaluator 设计

## 状态

- 日期：2026-08-17
- 状态：设计已确认，书面规格等待审阅
- 目标：建立一个可重复执行、可读、可在 CI 阻断回归的 evaluator，并依据其首轮审查结论修复 eqlib 的依赖、数据与数值风险。

## 背景

eqlib 是面向 A 股回测与研究的事件驱动库。它的结果同时依赖 Python 数值栈、机器学习栈、交易日历、AkShare 及若干直接 HTTP 数据源。只要依赖升级、安装解析、上游 schema、网络降级或浮点/索引语义发生变化，就可能在代码没有改动时改变回测、风险告警或模型结论。

首轮只读对抗审查已经确认以下可复现问题：

1. 依赖没有 lock/constraints/hash；`requirements.txt`、`pyproject.toml`、运行时导入和当前 editable 元数据互不完全一致。`requests` 被直接导入但没有直接声明，当前工作区的旧 editable 元数据还掩盖了低于源码要求的 scikit-learn。
2. 腾讯回退行情目前可将价格缩小 100 倍、成交额缩小约 10 倍，并返回超过请求区间的历史数据；基础 OHLCV 校验仍会接受它。
3. `chinese_calendar` 的法定工作日并不等于沪深交易日。离线回退日历在 2024 年把 2024-02-09 错当为开市日，且未来年份覆盖不足时会退化为不可靠推测。
4. 组合风控、风险度量和 ML 路径存在可由合成输入重现的错误，包括未生效的最大回撤熔断、按策略等权而非 NAV 加权的 VaR、错误的下行偏差、标签错配、单类别概率语义错误和预测批次依赖。
5. 现有测试混合离线与真实网络调用；部分联网测试在接口整体失败时仍然通过，因为只断言返回类型或在非空分支才检查 schema。

本设计不把“evaluator”描述为对未来绝对无误的承诺。它的保证方式是：把已知高风险类别转成有证据、有阈值、可重复、可阻断的检查，使同类问题不能在未被报告的情况下进入受保护分支或发布流程。

## 目标

完成后，项目应具备以下能力：

- 在干净隔离环境中验证发布 wheel 的实际依赖元数据、解析结果和运行时导入，而不是信任开发机的 editable 安装状态。
- 对核心依赖调用建立冻结输入的对抗契约：schema、单位、日期、完整性、有限性、索引对齐、随机性、错误语义与退化路径均可验证。
- 将数值正确性从“没有异常”升级为独立 oracle、金样结果和变形不变量验证。
- 将性能检查绑定到受控基线：冷导入、关键数据路径、缓存路径和科学计算不得出现显著同环境回归。
- 生成人可读 Markdown 和机器可读 JSON 报告，包含环境证据、发现编号、严重级别、复现信息、影响、建议和门禁结果。
- 在普通 PR 提供确定性离线门禁；在定时、手动和发布前任务中运行低频、有限预算的真实联网健康检查。
- 依据报告修复首轮 P0/P1 问题，并由相同 evaluator 证明修复有效且不回归。

## 非目标

- 不把真实供应商的可用性、市场数据真实性或未来投资结果承诺为绝对保证。
- 不在普通 PR 中对第三方服务实施高并发、故障注入或无边界重试。
- 不把 evaluator 变成新的公共 eqlib API；它是仓库维护与发布质量工具。
- 不在第一轮重构所有数据接口或替换所有依赖。修改只覆盖经审查证明会影响稳定性、可靠性、准确性、精度或性能的问题。
- 不把依赖漏洞扫描的瞬时网络结果作为唯一发布事实；报告必须记录扫描时间、数据库/工具版本和解析环境。

## 方案比较与选择

### 方案一：仅静态依赖扫描

扫描 `pyproject.toml`、导入和漏洞数据库即可快速得到清单，但无法验证 wheel 元数据、数值公式、数据源单位、日期范围或缓存/退化路径。它不能发现本轮腾讯和风险计算 P0。

### 方案二：仅补充 pytest 单元测试

它适合验证逻辑，但没有统一报告、依赖解析证据、真实上游健康信息或性能证据，且难以区分普通回归测试和依赖对抗审查。

### 方案三：分层 evaluator + 对抗契约 + 双通道 CI（选定）

选定方案由一个专用 CLI 编排静态、隔离环境、离线契约、性能和可选联网检查；所有结果归一化为同一份报告。确定性检查在 PR 阻断，真实网络检查与其隔离。该方案覆盖首轮发现，同时避免把供应商短暂故障变成每个开发分支的随机失败。

## 总体架构

```text
源码 / 依赖声明 / 锁定文件 / CI 配置
        │
        ▼
依赖清单与供应链审计 ───► 隔离 venv 构建 wheel ───► wheel 元数据 / 解析树 / SBOM
        │                                            │
        ├────────────────────────────────────────────┤
        ▼                                            ▼
离线对抗契约（fixture、oracle、变形测试）      性能基线（受控子进程）
        │                                            │
        └───────────────► 统一 finding 模型 ◄────────┘
                                │
                可选：联网健康探针（低频、总预算）
                                │
                                ▼
                    report.json + report.md + exit code
                                │
                     PR 门禁 / 定时告警 / 发布门禁
```

Evaluator 实现保持四个边界清晰的层：

1. **清单与隔离环境层**：读取声明，AST 扫描第三方导入，在临时虚拟环境构建并安装 wheel，比较来源声明、wheel `METADATA`、安装元数据、锁定解析和 `pip check`。
2. **离线对抗契约层**：使用冻结的原始供应商 payload 与合成数值输入，验证标准化、错误语义、金样结果和不变量；此层不访问网络。
3. **联网健康层**：只读取少量代表性标的和 endpoint，记录版本、延迟、schema 指纹、来源状态与跨源量级；它不能修改数据、缓存或远程系统。
4. **报告与门禁层**：把任一层的证据转换为稳定 finding ID 和 P0–P3 严重度；统一输出 Markdown/JSON，并通过 profile 决定是否返回非零状态。

## 命令与运行档位

新增仓库维护命令（最终名称以实现为准）：

```bash
python scripts/evaluate_eqlib_dependencies.py --profile offline --output artifacts/eqlib-evaluator
python scripts/evaluate_eqlib_dependencies.py --profile live --output artifacts/eqlib-evaluator
python scripts/evaluate_eqlib_dependencies.py --profile offline --strict
```

### `offline`

必须可重复、无网络、适合每个 PR。它执行：

- wheel 构建与干净 venv 安装验证；
- 声明/导入/extra/lock 一致性审查；
- 固定数据源 payload 的 canonical schema、单位、范围、缺口、错误与缓存契约；
- 数值 oracle、金样、随机种子、变形与负例测试；
- 受控性能子进程基线比较。

### `live`

在 `offline` 通过后增加低频网络探针。每个 endpoint 有连接/读取超时、总 deadline、请求数量和并发上限；网络错误在报告中标识为外部可用性发现，只有发布或显式严格模式才作为门禁。它不会对远程服务做故障注入。

### 严重度与退出码

| 级别 | 含义 | `offline --strict` | 定时 `live` | 发布 `live --strict` |
|---|---|---:|---:|---:|
| P0 | 会产生错误数据/结论、无法安装或绕过安全门禁 | 失败 | 告警 | 失败 |
| P1 | 可靠性/兼容性/完整性高风险 | 失败 | 告警 | 失败 |
| P2 | 可维护性、可观测性或性能回归风险 | 报告 | 告警 | 配置化 |
| P3 | 改进建议 | 报告 | 报告 | 报告 |

普通 PR 不运行真实网络探针；它由定时任务、手动触发和发布候选触发。这样既保留实时信号，又不把第三方短暂波动伪装成代码回归。

## 发现与报告数据模型

每个 finding 至少包含：

- 稳定 ID，例如 `DEP-001`、`DATA-101`、`NUM-201`、`PERF-301`；
- 严重度、标题、状态（open/fixed/regressed/unavailable）；
- 受影响的文件、依赖、endpoint 或函数；
- 可审计证据：环境、输入 fixture/摘要、实际值、期望值、容差、耗时、异常和命令；
- 影响说明、确定修复建议与对应回归测试；
- `profile`、运行时间、Python/OS、wheel hash、依赖解析树和工具版本。

`report.md` 以风险摘要、通过/失败门禁、按领域的发现、性能表和修复验证为主体。`report.json` 是同一事实的结构化表示，供 CI artifact、趋势分析和后续自动化读取。报告不得把 API 失败或未知数据表示成零值、完整数据或“通过”。

## 依赖与供应链契约

### 单一依赖事实源

`pyproject.toml` 是发布声明的事实源。若保留 `requirements.txt`，它必须由受控输入生成并覆盖同一主依赖集合；否则删除它和相关文档入口。运行时直接导入的第三方包必须恰好归属为主依赖、明确 extra 或受控可选 provider。

首轮修复必须：

- 显式声明 `requests`；
- 使 scikit-learn、chinese-calendar、主依赖清单和文档一致；
- 为 `fastparquet`、`xgboost` 明确 extra，或使不可用时的错误语义可见且受测；
- 统一 Python 支持承诺。基线选择为 `>=3.10`，因为现有 classifiers、README、安装文档和 CI 已以 3.10–3.12 为实际范围；同步中英文文档与元数据。

### 隔离 wheel 验证

Evaluator 不得把当前开发环境的 `pip check` 作为项目健康结论。它必须在临时目录中：

1. 构建 wheel；
2. 新建 venv；
3. 安装 wheel 和选定锁定解析；
4. 读取 wheel/安装后的 `METADATA`、`Requires-Python` 和 `Requires-Dist`；
5. 运行导入烟雾、`pip check` 与受控依赖清单比较；
6. 将 wheel hash、解析报告和环境快照写入报告。

锁定策略使用带 hash 的、可再生成的约束文件；发布包仍保留兼容范围。至少包含一个锁定的当前解析和一个最低兼容解析，以区分依赖升级回归与最低版本兼容问题。

## 数据源对抗契约

### Canonical OHLCV

所有供应商输出在进入回测、缓存或 fallback 前都必须满足：

- 唯一、单调递增、无 `NaT` 的日期索引；
- 请求范围内的严格裁剪和明确的首尾/中间交易日覆盖状态；
- 正且有限的价格，`low <= min(open, close) <= max(open, close) <= high`；
- 非负且有限的成交量和成交额；
- 明确的单位、复权模式、来源、schema 版本、抓取时间和质量状态；
- 无法满足完整性时返回明确的 `incomplete` / `unavailable` 状态，严格模式抛出结构化错误，不得静默伪装为完整数据。

离线 fixture 保留原始供应商响应的最小可审计片段，而不是只 mock 已规范化的 DataFrame。覆盖腾讯数组重排、HTML/非 JSON、429/5xx、超时、字段缺失、乱序/重复日期、错误单位、尾部缺失、负成交量和 OHLC 包络违例。

### 腾讯与多源回退

首轮修复先将腾讯回退源从默认可接受路径中隔离，直到其单位经多标的、多日期的冻结 fixture 与跨源量级比较确认。修复后所有来源必须由同一日期裁剪与 canonical validator 处理；低价格但形状正确的数据也必须因单位/跨源比例异常而被拒绝或标记。

跨源联网探针选择一个流动性股票、ETF、指数和交易日历 endpoint。它记录而非要求逐点相同的价格，但必须对价格、成交额和成交量量级设置容忍比例，并报告 schema 指纹、行数、最早/最晚日期、来源链和耗时。

### 交易日历

离线交易日历必须由版本化、可审计的沪深交易所日历数据提供；`chinese_calendar` 只能作为辅助信号，不能把法定调休工作日推断为开市日。覆盖年份之外必须显式报错或降级为不可用，绝不能臆测交易日。固定回归样例至少包括 2024-02-09 非交易日。

### 外部错误与缓存

统一的数据源客户端负责有界 timeout、仅幂等请求的重试、退避/jitter、429/5xx 分类、来源级并发/速率预算、总 deadline 和可观测失败原因。缓存只能保存已通过 canonical validator 的数据，并以来源、复权、schema/validator 版本和抓取时间记录 provenance。中间交易日缺口、损坏文件、metadata 与数据不一致、并发同键和可变返回值都必须有对抗测试。

历史参数如 `date` / `trade_date` 必须真正约束 as-of 数据；若上游没有历史能力，API 必须显式拒绝在回测中使用，不能返回当前快照造成前视偏差。

## 数值、统计与 ML 对抗契约

离线数值测试使用独立 NumPy/Pandas oracle 或冻结金样，禁止仅重用被测函数的实现逻辑。每项检查同时覆盖正常值、NaN、Inf、零、负值、乱序、重复索引、缺失日期和边界参数。

首轮 P0 修复及其 evaluator 规则包括：

| 领域 | 必须成立的契约 | 首轮修复方向 |
|---|---|---|
| 组合风控 | 30% 合成回撤触发最大回撤熔断；新增风险不得降低告警等级 | 计算并比较 portfolio/strategy MDD；用显式数值优先级聚合 alert |
| VaR | 不等 NAV 策略按同日 NAV 权重而非策略数等权；日期对齐策略可见 | 按净值权重构造组合收益，并报告/拒绝覆盖不足 |
| 下行风险 | LPM2 对所有观测计算，VaR/CVaR 符号与置信度语义统一 | 修正公式、输入校验和跨模块语义 |
| 收益曲线 | list/dict、乱序/排序、初始资金和缺口策略有一致且明确结果 | 建立单一规范化收益/净值路径，禁用隐式 `pct_change` 填充 |
| ML 对齐 | 任意标签索引置换与显式 `.reindex` 参考模型一致 | 以共同、有序、唯一索引对齐 X/y |
| ML 概率 | 全零/全一/非二元标签下，`P(class=1)` 由 `classes_` 决定 | 按类别位置选择，缺失正类返回零 |
| ML 推理 | 同一行单独预测、拆分批次或加入无关行结果一致 | 训练期拟合 imputer，预测期只 transform，拒绝非有限输入 |
| 随机统计 | 同一 `random_state` 的 bootstrap/Monte Carlo 结果可重现 | 暴露、记录并验证随机种子 |

变形测试至少包含：乱序输入等价于排序输入；list schema 等价于 dict schema；增加风险不降低告警；预测批次拆分/合并不改变同一行；同一 seed 产生同一结果；不可行优化问题产生可诊断错误而非无效权重。

## 性能契约

性能检查不以不同硬件上的绝对秒数作为门禁。每项基准在隔离子进程中多次测量中位数，并与受控 runner 的版本化基线比较。首轮覆盖：

- `import eqlib` 的冷导入时间和峰值 RSS；
- canonical 数据标准化、缓存命中/未命中、区间裁剪和 fallback 上限；
- 风险滚动计算、bootstrap/Monte Carlo、优化器及常用指标；
- 50k/252 窗口的 percentile rank、CCI/WMA 等已知热点；
- ML 调参的并行度，禁止外层与 estimator 同时无边界 `n_jobs=-1`；
- 报告生成的 figure 生命周期和并发泄漏。

默认阈值为同环境基线中位数的相对回归上限（初始为不超过 2 倍），同时记录样本规模、CPU、Python、依赖版本和峰值内存。只有经审阅的 `--update-baseline` 运行才可以更新版本化基线。

## CI 与发布集成

1. 新增 evaluator workflow：Linux 上运行支持的 Python 3.10–3.12 离线档位，保存 Markdown/JSON 作为 artifact；至少一个 job 使用锁定当前解析，另一个覆盖最低兼容解析。
2. 普通 PR 运行 `offline --strict` 与既有核心测试，网络相关现有测试改为显式 marker，避免空结果通过。
3. 定时和手动 workflow 运行 `live`，上传结果并在 P0/P1 时清晰告警；发布候选运行 `live --strict`。
4. 生产 Linux 平台必须运行完整 `tests/`；macOS 可保留为额外兼容覆盖，而不是唯一核心平台。
5. 工作流 action、Docker 基础镜像和锁定依赖的固定性作为供应链审查项，报告其 SHA/digest/hash 状态。

## 实施边界

预期新增/修改的主要区域：

- `scripts/`：evaluator CLI 与可重现的依赖锁定/报告辅助工具；
- `tests/`：evaluator 自测、供应商 raw fixture、数据/日历/缓存/数值/ML 的离线对抗契约与性能基线；
- `eqlib/data.py`、`eqlib/data_cache.py`：canonical 标准化、错误/质量状态、日历、腾讯回退和日期语义修复；
- `eqlib/portfolio_risk.py`、`eqlib/utils/stats.py`、`eqlib/ml/models.py`，以及必要的共享收益规范化模块：首轮已证明的数值 P0 修复；
- `pyproject.toml`、依赖约束文件、CI workflow：依赖声明、锁定、marker 和门禁；
- 中英文安装/FAQ/安全文档：支持范围、安装入口和 evaluator 使用方法。

公共 API 如需新增 strict 或质量状态，只允许采用向后兼容的显式参数/结果字段；任何不兼容改变必须单独说明并更新参考文档与示例。

## 验收标准

完成必须同时满足：

- `offline --strict` 在干净环境通过，并生成没有 P0/P1 open finding 的 Markdown 与 JSON 报告。
- evaluator 能在故意引入的未声明导入、wheel metadata 不匹配、错误腾讯单位/越界日期、错误交易日、回撤不触发、标签错配或预测批次依赖时失败，并给出稳定 finding ID。
- 首轮 P0 修复有独立 oracle/fixture 回归测试；同一 evaluator 对修复前失败、修复后通过。
